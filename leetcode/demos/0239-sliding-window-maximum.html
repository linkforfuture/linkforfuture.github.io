1先记住一句话

这个 deque 不是窗口。它是一份「还没被淘汰的候选人名单」，里面存的是下标，对应的值从头到尾严格递减。

队首 = 当前窗口的最大值。仅此而已。

⚠️ 最容易踩的前提误解：deque 自己不会排序。这个「递减」是步骤①那个 while 循环手动维护出来的，容器完全不知道里面的值是有序的。详见第 4 节第一条。

步骤① 队尾淘汰：nums[dq.back()] <= nums[i] 就弹掉。
理由：来了个又新又大的。那些又旧又小的，等 nums[i] 都过期了它们更早过期，永远轮不到它们当最大值 —— 它们已经死了，只是尸体还留在队列里。
步骤② 自己入队：dq.push_back(i)。
注意存的是 下标 i 而不是值 —— 因为后面要判断「过期」，必须知道它在哪个位置。
步骤③ 队首过期：dq.front() <= i - k 就弹掉。
窗口是 [i-k+1, i]，队首下标 ≤ i-k 说明它已经滑出左边界了。因为它最大，一直赖在队首，所以只需要检查它一个。
步骤④ 记录答案：窗口形成后（i >= k-1），nums[dq.front()] 就是答案。
为什么队首最大？因为整个队列是递减的，左边那个就是老大。

为什么是 O(n) 而不是 O(nk)？

每个下标 最多入队 1 次，也最多出队 1 次（无论从队首还是队尾出去）。所以整个循环里 pop 的总次数 ≤ n。虽然有个 while 套在 for 里，但它是均摊 O(1) 的 —— 不是每个 i 都会弹很多次，前面弹得多，后面就没得弹了。

4几个卡住人的点


  

    deque 里面是按什么规则排序的？
    

      
不排序。std::deque 就是一个「两头都能 O(1) 进出的数组」，push_back 把元素扔到末尾，它不做任何比较，也不知道里面的值是有序的。

      
那个「递减」是算法的 while 循环手动维护出来的，不是容器的功能。如果只执行 dq.push_back(i) 这一行，往空队列里依次塞 7、2、5，你会得到 [7,2,5] —— 乱序。

      

        
队列当前是 [7, 2]，现在要插入 5：

        
有 whilenums[2]=2 ≤ 5 → 弹掉 2 → push 5 → [7, 5] ✓ 仍递减

        
没 while直接 push 5 → [7, 2, 5] ✗ 递减被破坏

      

      
所以「单调队列」这个名字，指的是 deque + 一套始终维持单调性的纪律。deque 只是被选中的容器，单调性是你自己写代码保证的。就像一个手写的「当前前三名」榜单 —— 榜单本身不会自动排序，是你每次录入新成绩时顺手把该划掉的划掉。

    

  


  

    那为什么不用 set 或 priority_queue？
    

      

        
容器插入取最大删除任意元素

        
dequeO(1)队首直接取能，但要自己找位置

        
set（红黑树）O(log n)O(1)，*rbegin()能，O(log n)

        
priority_queue（堆）O(log n)O(1)不能，只能懒删除

      

      
set 也能做出正确答案，总复杂度 O(n log n)。单调队列能做到 O(n)，是因为它额外利用了「过期顺序是 FIFO」这个结构信息 —— 越早入队的越早过期，所以从队首删就够了。堆没有这个顺序，所以堆的解法必然慢一档。

      
另外 vector 不能用：它的 pop_front() 要把后面所有元素整体前移，是 O(k)，总复杂度会退化成 O(nk)。

    

  


  

    为什么弹出条件是 <= 而不是 <？
    
用 <= 是为了把相等的旧元素也弹掉，让队列里同一个值只保留最新的那个。

    
两种写法结果都对（相等时留谁都不影响最大值）。但保留最新的下标更「耐用」—— 它更晚过期，能多撑一会儿。所以是习惯上的最优写法，不是正确性要求。

  


  

    为什么队列里存下标，不直接存值？
    
因为步骤③需要判断过期：得知道这个元素当初在数组的哪个位置，才能算出它有没有滑出左边界。

    
只存值的话，一旦队首和某个新来者数值相同，你就分不清队首到底是哪个位置的了。下标是身份证，值只是属性。

  


  

    步骤①和步骤③的顺序能换吗？
    
能，但要注意一个边界：如果 k = 1，先处理别的容易出岔子。目前这个顺序（先弹队尾 → 再入队 → 再弹队首）是最稳的，因为入队之后队列一定非空，步骤③访问 dq.front() 时不需要额外的空判断。

    
官方的另一种常见写法是先弹队首再弹队尾，也可以，但必须写成 while 而不是 if（虽然实际最多只弹一个，写 if 也行）。

  


  

    为什么步骤③只用 if 不用 while？
    
因为下标是递增入队的（0,1,2,... 依次 push），队列内部下标一定是从小到大排列。所以队首是最旧的那个——它要是没过期，第二个更不可能过期。最多弹一个。

    
反过来说，如果队首过期了，弹掉之后新的队首是下一个较新的下标，它一定在窗口内，不用再循环判断。

  


  

    while 里那一堆 pop_back，开销为什么不算进复杂度？
    

      
算进去了，而且算出来的总量小得惊人。关键就一句话：元素一旦被 pop_back() 弹掉，就永远不会再被访问。

      
于是可以数总量：

      
    
        
  • 每个下标入队恰好 1 次 → 总共 n 次 push_back
    • 
        
  • 每个下标出队至多 1 次（从队首弹、从队尾弹、或留到最后）→ 总共 ≤ n 次 pop
    • 
        
  • while 条件判断：失败退出每次迭代 1 次（≤ n），成功进循环每次对应一次 pop（≤ n）
    • 
      

      
三者相加 ≤ 3n。也就是说，那个嵌套 while 的循环体，在整个算法的一生中最多执行 n 次 —— 不是每次迭代 n 次。

      

        
+2push_back 的时候，往这个元素身上贴 2 块钱

        
−11 块当场付掉「入队」这个动作本身

        
存另 1 块存在元素身上，等它将来被弹出时用来付账

        
−1被弹出时，用它自己身上那 1 块钱付清，不欠债

        
总收入 2n，总支出 ≤ 2n → O(n)

      

      
每个元素最多被弹一次，所以每笔弹出的账都由它自己预付的钱付清，不需要额外借钱。均摊到 n 次迭代，每次 O(1)。

    

  


  

    单次迭代真的可能很贵吗？
    

      
会。要分清「均摊 O(1)」和「每次都是 O(1)」：

      

        
构造一个最坏情况

        
nums = [5, 4, 3, 2, 1, 100]，k = 3

      

      
前 5 次循环，队列一路长成 [5,4,3,2,1]，一个都没弹。然后 i=5 遇上 100，一次性把 5 个全弹光，那一步确实是 O(n)。

      
但这 5 次弹出的钱不是凭空来的 —— 是前面 5 次入队时预付的。整体算总账不变。这正是摊还分析的意义：允许个别步骤很贵，只要贵的理由在之前已经预付过。

    

  


  

    队列里是不是一直装着整整 k 个元素？
    
不是，而且通常比 k 少得多。步骤①会大量淘汰，队列里只留「从右往左看，一个比一个大的那些」—— 也就是所谓的「后缀最大值」序列。

    
极端情况下（数组完全递减，比如 [9,8,7,6,5], k=3），没有任何元素被步骤①弹掉，队列里就是整整 k 个。反过来数组递增时，队列永远只装 1 个。

  


  

    「窗口滑动」到底体现在哪一步？
    
窗口滑动的唯一动作就是步骤③ —— 把左边界以外的旧元素踢出去。右边界是靠 for 循环的 i 前进实现的。

    
而窗口「还没形成」的阶段（i < k-1），只进不出，所以循环里有个 if (i >= k-1) 才记录答案。

  







  
5思想内核：二维支配与 Pareto 前沿

  
这道题表面教的是「单调队列」，但把这个数据结构忘掉，剩下的是一个更普适的东西。


  
5.1每个元素其实有两个属性

  
把每个元素看成一个带两个属性的点，而这两个属性都是越大越好：

  

  

    
属性符号含义方向

    
值nums[j]有没有资格当最大值越大越好

    
寿命j（下标）什么时候过期出局越晚越好

  

  

  
对两个下标 j < i，如果 nums[j] ≤ nums[i]，那么：值维度上 i 不输，时间维度上 i 活得更久。

  
j 在两个维度上全面劣于 i —— 这叫 i 支配（dominate） j。被支配的元素是永久无用的：只要 i 还活着，最大值轮不到 j；等 i 死了，j 早就死透了。可以从状态里永久删除。


  

    

      
旧元素  j = 下标 4，值 3

      
新来的  i = 下标 5，值 5

    

    

      

        
值3

        
寿命到 i=4

      

      

        
值5 ✓

        
寿命到 i=5 ✓

      

    

    
两根柱子都更长 → j 被全面压制 → 永久删除

  

  
（这组数字就是第 2 节动画里 i=5 那一步真实发生的事。）


  
5.2于是：队列里存的是 Pareto 前沿

  
把所有被支配的元素删掉之后，剩下的就是那些互相不可比的元素 —— 谁也不能全面压制谁。这正是二维偏序下的 Pareto 最优集：值大的活不长，活得久的值不大，两个目标互相拉扯，一个都不能删。


  

    
队首队尾

    

      
队首 = 值维度最优值最大，最可能赢；但最旧，最快过期

      
队尾 = 时间维度最优最新，活得最久；但值最小，最不可能赢

    

    
整个队列就是从「值优先」到「时间优先」的权衡前沿

  


  
这个视角一下子解释了三件看起来奇怪的事：

  
    
    
  • 为什么队首就是最大值？→ 队首是值维度的最优点
    • 
    
  • 为什么队列一定递减？→ 从队首到队尾，就是在用值换寿命
    • 
    
  • 为什么只弹队尾、不弹中间？→ 新元素在时间维度上必然最优，它只能支配那些值也不如它的元素，而那些恰好都堆在队尾
    • 
  


  
5.3三个可迁移的通用原理

  

    

      
1主动维护不变量，用维护成本换查询成本

      
deque 本身什么都不会，是代码每时每刻维持着「递减」这个不变量，才把「取最大值」退化成了「看队首」这一个 O(1) 动作。而且它只需要部分有序（递减即可）而非全序，所以维护成本比堆的 O(log n) 还低。
        
同族：堆（维护堆序换 O(1) 取极值）、并查集（维护扁平化换近 O(1) 查询）、前缀和（维护累加换 O(1) 区间和）

      

    

    

      
2摊还分析：让每个元素一生只被处理常数次

      
每个元素入队一次、出队一次 → 总代价有上界 → 个别步骤再贵也不怕。识别特征是「单调前进的指针」或「一生只删一次的元素」。
        
同族：KMP 的 j = next[j] 回退（每次最多 +1，回退总量 ≤ 前进总量）、并查集路径压缩、vector::push_back 扩容、Manacher 回中心扩展

      

    

    

      
3识别问题特有结构，把通用工具从 O(n log n) 打到 O(n)

      
set / 堆都能做出正确答案，代价 O(n log n)。但注意到「过期顺序 = 入队顺序」这个额外结构后，就能 O(n)。通用数据结构给你 O(log n)；识别出问题特有的结构，往往能拿到 O(1) —— 代价是解法不再通用、更难维护，这是一次有意识的权衡。
        
反面：如果淘汰顺序不是 FIFO（比如按优先级淘汰），这个结构就不存在了，只能老老实实用堆

      

    

  


  
5.4判别法：什么时候该想到它

  
四个条件同时成立就该警觉：

  
    
    
  • 1有滑动窗口，或任何固定长度的连续区间
    • 
    
  • 2求区间内的 max / min（求 sum 请用前缀和，不是它）
    • 
    
  • 3窗口单向移动，从前往后不回退
    • 
    
  • 4需要 O(n)，不接受 O(n log n)
    • 
  

  
但真正的本质判据只有一句：存在支配关系，且被支配者能被永久删除。


  
5.5变形矩阵：改一个维度，得到另一个算法

  

  

    
改动得到什么

    
比较方向 ≤ 改成 ≥滑动窗口最小值

    
去掉时间维淘汰（步骤③）单调栈 —— 解决「下一个更大元素」

    
去掉值维淘汰（步骤①）普通队列 —— 滑动平均 / 定长区间和

    
窗口大小不再固定双指针 + 单调队列（如 LC 1438）

    
同时挂两个队列（一增一减）同时维护区间的 max 和 min

    
存的不是 nums[j] 而是 dp[j] + w(j)单调队列优化 DP（见 6.1，回报最高的一条）

  

  


  

    一句话总结这个思想：当新来的元素在两个维度上都压制了旧的元素，旧元素可以永久删除。于是候选集始终只剩「互相不可比」的那一小撮，答案必在其中某个固定位置（队首），而淘汰的总代价被摊还成 O(1)。

6.1回报最高的迁移：单调队列优化 DP

  
一大类 DP 的形状是长这样的：

  
通用形状dp[i] = max{ dp[j] + w(j) }   ,  j ∈ [i-k, i-1]

  
把滑动窗口里装的 nums[j] 整个换成 dp[j] + w(j)，k 就是转移的跨度限制。代码结构一字不改，转移从 O(k) 降到 O(1)，整体从 O(nk) 降到 O(n)。


  
以 LC 1696 跳跃游戏 VI（dp[i] = nums[i] + max(dp[j])）为例，和本题并排看：


  

    
本题 LC 239 —— 窗口里放 nums[j]for (int i = 0; i < n; ++i) {
    while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front();          // 窗口 [i-k+1, i]
    if (i >= k - 1) result.push_back(nums[dq.front()]);
}


    
LC 1696 —— 窗口里放 dp[j]vector<int> dp(n);
deque<int> dq;                                       // 存下标 j，dp[j] 递减
dp[0] = nums[0];
dq.push_back(0);
for (int i = 1; i < n; ++i) {
    while (dq.front() < i - k) dq.pop_front();       // 窗口 [i-k, i-1]
    dp[i] = dp[dq.front()] + nums[i];             // 转移 O(1)
    while (!dq.empty() && dp[dq.back()] <= dp[i]) dq.pop_back();
    dq.push_back(i);
}
return dp[n - 1];

窗口[i-k+1, i]，含 i 自己[i-k, i-1]，不含 i

    
队列里装的抽象量nums[j]dp[j]

    
入队前的比较nums[dq.back()] ≤ nums[i]dp[dq.back()] ≤ dp[i]

    
取答案result.push_back(nums[dq.front()])dp[i] = dp[dq.front()] + nums[i]

6.3更远的地方：支配关系到处都在

  
「删除被支配的候选者」这个想法，换了外衣反复出现：

  

    

      
凸凸包（Andrew's monotone chain）

      
三个点里中间那个如果被两端「压住」（不在凸包上），就永久删除。保留的还是 Pareto 前沿 —— 只不过两个维度换成了「x 坐标」和「斜率」，而维护手法仍然是单调栈。
      

    

    

      
斜斜率优化 DP

      
决策点 (x_j, y_j) 里，被支配的决策点永远不会最优，于是用单调队列 / 单调栈维护一个下凸壳，转移取切线即可 O(1)。和本题是同一个思想的二维几何版本。
      

    

    

      
单决策单调性 / Knuth 优化

      
最优决策点随 i 单调不减 → 一大批候选被「结构性支配」，可以整体跳过。这是支配关系在决策空间里的投影。
      

    

  


  
6.4反过来：什么时候不该用它

  
强上单调队列只会把代码写复杂，还丢掉了 O(n log n) 解法的可读性。

  

  

    
需求该用什么

    
区间求和 / 求积前缀和，别绕远

    
窗口两端都会回退（如 LC 76 最小覆盖子串）双指针 + 计数；元素剪不掉，没有支配关系

    
需要随机访问窗口内任意元素（如区间第 k 大）有序容器 / 可持久化结构

    
淘汰顺序不是 FIFO（按优先级淘汰）堆。结构前提不成立，O(n) 拿不到
