翻转二叉树：递归图解

LeetCode 226 · 递归想不通，通常不是代码难，而是脑海里缺一个画面。这一页把调用栈摊开：函数怎么下去、在哪儿触底、怎么带着「翻好的子树」回来、交换为什么发生在回程。

难度：简单 树 · 递归 · DFS 时间 O(n) 空间 O(h)

题目

给你一棵二叉树的根节点 root，翻转这棵二叉树，并返回其根节点。翻转的含义是：树里每一个节点的左右孩子都互换位置。

提示：树中节点数目范围 [0, 100]；-100 <= Node.val <= 100。原题：LeetCode 226. 翻转二叉树 ↗

先搭心智模型：把递归当成一份契约

递归读不通，几乎总是因为想做一件人脑做不到的事：同时跟踪所有层。三层递归就有三个「进度」悬在半空，越想越乱。正确的做法是每次只看一层，其余全部交给一份契约。

invertTree 的契约：给我任何一棵子树的根（哪怕是空指针），我还你同一棵树，但里面每个节点的左右孩子都已经互换。

读代码时，把每一次 invertTree(...) 调用都当成一个必定兑现契约的黑盒。不要去想它内部怎么实现——那正是它自己的事。

有了契约，整段代码只剩下三个问题要回答：

  1. 什么时候不用干活？ 空树没有孩子可换，原样返回 nullptr（第 4–5 行）。
  2. 怎么把问题变小？ 把左子树、右子树分别整棵交出去（第 7–8 行）。
  3. 拿到结果后，我这一层做什么？ 把两棵「已经翻好」的子树对调挂回自己身上，然后交还（第 9–11 行）。

三问答完，代码就读完了。下面这张图是第 3 问的画面：站在任何一个节点上，你看到的永远是两个黑盒加一次对调。

代码的两个方向

这份代码同时在两个方向上跑，把它拆成三段就不绕了：

  1. 第 4–5 行 · 刹车空树直接返回。递归能停下来的唯一原因，也是所有树递归的第一行肌肉记忆。
  2. 第 7–8 行 · 下去（只拆不改）把「翻转我的左子树」「翻转我的右子树」两个子任务派出去，然后停在原地等结果。下降路上没有任何节点被修改。
  3. 第 9–11 行 · 上来（组装交换）两棵成品到手，互换挂回，再把自己交还上一层。翻转这个动作 100% 发生在回程，所以是自底向上完成的。

最常见的思维陷阱：盯着 invertTree(root->left) 想「它里面又要调用自己，那里面又要调用自己……」。这条链永远想不完。你只需要知道两件事：它一定会停（有刹车），停住之后一定兑现契约（还你一棵翻好的子树）。剩下的交给调用栈，不是交给你的脑子。

对照代码

高亮的那几行，就是当前这一步正在执行的代码。

class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        if (root == nullptr) {
            return nullptr;
        }
        TreeNode* left = invertTree(root->left);
        TreeNode* right = invertTree(root->right);
        root->left = right;
        root->right = left;
        return root;
    }
};

逐行拆解

行代码它在做什么
4–5if (root == nullptr) return nullptr;刹车。空树没有孩子可换，原样返回。没有它，调用会顺着不存在的孩子无限冲下去
7TreeNode* left = invertTree(root->left);把左子树整棵托付给下一层，然后停在这一行等结果。等到的 left 是「已经翻好的左子树」
8TreeNode* right = invertTree(root->right);同理托付右子树。注意此时还没有任何指针被改动
9–10root->left = right; root->right = left;全题唯一的实际动作：两根孩子指针互换。O(1)，不复制任何节点
11return root;把「已经翻好的自己」交还上一层，兑现契约

第 7、8 行的 left / right 是两个局部变量，作用相当于两只手：先把两棵成品子树都拿稳，再动 root 的指针。这一点是下面第一个疑问的答案。

几个卡住人的点

为什么必须先用 left / right 存起来，不能直接写进赋值？

因为第 9 行一旦执行，root->left 里原来那个指针就被覆盖掉了。如果不先存进局部变量，原左子树从此再也找不回来。

// 看起来更短的错误写法
root->left  = invertTree(root->right);   // ① 左指针被覆盖，原左子树丢失
root->right = invertTree(root->left);    // ② 这里的 root->left 已经是「翻好的右子树」了
设原来左孩子是 1、右孩子是 3，看看两种写法的结局：
错误写法② 又把右子树翻了一遍（翻了两次等于没翻），而节点 1 那棵子树整棵丢失，永远没人翻它
你的写法两个结果先落在 left / right 上，root 的指针随后怎么改都不影响它们，两棵子树各翻一次、恰好一次

等价的写法是 std::swap(root->left, root->right)——它内部同样借助临时变量，只是替你写好了。

交换为什么放在递归之后？放到递归之前行不行？

行，而且同样正确。你这份代码把交换放在后序位置（两个孩子都处理完之后）；也可以放在前序位置（先换再递归）：

if (root == nullptr) return nullptr;
std::swap(root->left, root->right);   // 先把两个孩子换个位置
invertTree(root->left);               // 再分别翻转（此时左右已经易位）
invertTree(root->right);
return root;

两种写法都保证「每个节点的孩子恰好被交换一次」，结果完全一样。区别只是交换发生的时机：后序版是自底向上翻好（叶子先完成，根最后），前序版是自顶向下翻好。

「当前节点的动作放在去程还是回程」是树递归里最值得练的直觉。这题两种都行，但很多题只有一种对——比如求树高，必须先拿到孩子的高度才能算自己的，只能在回程做。

叶子节点为什么要白走一遍交换？

因为这份代码只认识「空」和「非空」，不认识「叶子」。叶子的交换是 swap(nullptr, nullptr)，什么也没发生，但流程一步没少。

这正是递归省力的地方：不写任何特判，几行代码就覆盖了任意形状的树。演示里第 6、11、19、24 步就是四次「交换两个空指针」，可以专门停下来看一眼。

递归靠什么保证一定会停？

靠两件事同时成立：

  1. 每个非空调用只会对严格更小的子树发起新调用，也就是每一步都在朝「空」靠近；
  2. 遇到空指针立刻返回，不再产生任何新调用。

树是有限的，所以调用链必然撞上第 4 行的刹车。写树递归时先写 base case，就是在先把这条保证钉死。

空间复杂度为什么是 O(h) 而不是 O(n)？

同一时刻栈里存放的，是「从根到当前节点」的一条路径，最长等于树高 h。n 是访问总量，h 才是同时在场的人数——递归的栈空间看后者。

平衡树 h = log n；退化成链表时 h = n，这是最坏情况。演示里这棵树最深时栈中有 4 帧（含触底那一帧）。

不用递归能写吗？

能。用队列做 BFS（或用显式栈做 DFS），每个节点出队时交换它的两个孩子，再把非空孩子入队：

if (root == nullptr) return nullptr;
std::queue<TreeNode*> q;
q.push(root);
while (!q.empty()) {
    TreeNode* x = q.front(); q.pop();
    std::swap(x->left, x->right);          // 做的事和递归版完全一样
    if (x->left)  q.push(x->left);
    if (x->right) q.push(x->right);
}
return root;

逻辑完全同构：访问每个节点一次，交换它的两个孩子。递归只是把「遍历所有节点」这件事交给调用栈免费代劳了。

这道「简单」题到底在考什么？

两样东西：递归信任（把子问题当黑盒，只处理当前一层）和后序思维（真正的组装发生在回程）。它们是所有树递归题的通用地基。

后面的题几乎都是同一个骨架——向左右子树各要一个结果，再组合成自己的答案：求高度要 max(左, 右) + 1，判对称要比较「左的左 vs 右的右」，合并树要把两棵树的对应节点接起来。把这题的调用栈画面建立起来，后面会省很多力气。

小结：把这套思路带走

写任何树递归，先回答三个问题

  1. 边界是什么？什么时候可以不做任何事直接返回。这题是 root == nullptr。
  2. 子问题的契约是什么？用一句话说清「给递归什么、它还你什么」。这题是「给一棵子树，还你它的镜像」。说清之后就不要再怀疑它。
  3. 当前这一层做什么？假设契约成立，我这层需要几步操作。这题是两次指针赋值。

想不通的时候，不要盯着代码硬想，拿一棵三五个节点的小树手工跑一遍——把每次调用、每个返回值写下来。这一页的演示做的就是这件事，只是替你写完了。

空树直接回，
左右各派一次活；
两手都拿稳，
指针一换就交货。

四句分别对应：第 4–5 行的刹车、第 7–8 行的两次递归、两个局部变量的意义、第 9–11 行的交换与返回。

同一套思路可以继续刷

  • 101 对称二叉树：把「翻转」换成「比较」，递归函数同时吃两个节点
  • 617 合并二叉树：两棵树同步下降，回程把结果接起来
  • 100 相同的树：与 101 同构，只是比较条件不同
  • 110 平衡二叉树：在求高度的回程里顺带判断，体会「为什么只能在回程做」
