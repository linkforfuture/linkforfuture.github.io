# 17. 电话号码的字母组合

> **难度**：中等　**标签**：回溯 · 深度优先搜索 · 字符串 · 哈希表
> **链接**：[LeetCode 17](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/)

## 题目

给定一个仅包含数字 `2-9` 的字符串，返回所有它能表示的字母组合。答案可以按**任意顺序**返回。

数字到字母的映射与电话按键相同（`1` 不对应任何字母）：

```
2: abc      3: def      4: ghi
5: jkl      6: mno      7: pqrs
8: tuv      9: wxyz
```

**示例 1**

```
输入：digits = "23"
输出：["ad","ae","af","bd","be","bf","cd","ce","cf"]
```

**示例 2**

```
输入：digits = ""
输出：[]
```

**提示**

- `0 <= digits.length <= 4`
- `digits[i]` 是范围 `['2', '9']` 的一个数字

## 我的理解

### 这道题的意义在于认识「回溯」本身

这道题的解法短得不像中等题，但它是我见过**最干净的一副回溯骨架**：没有剪枝、没有去重、没有冲突判断，只有「做选择 → 递归 → 撤销选择」三步循环往复。把这三步看清楚，46 全排列、78 子集、51 N 皇后那些题就是换汤不换药。

先说清楚回溯到底在干什么：

> **回溯 = 在一棵「决策树」上做深度优先搜索。**
> 每一步做一次选择，沿着这条路一直往下走；走到头了，就**退回上一步**，把刚才的选择**撤销**掉，换下一个选择继续走。

名字里的「回溯」（backtrack）说的就是这个「退回去」。它和普通 DFS 的唯一区别是：**它改了状态，并且改完必须自己还原。**

### 把这道题摊开成一棵决策树

`digits = "23"`，答案是 9 个。这 9 个答案不是「算」出来的，是**长**出来的——每一层为一位数字选一个字母：

```
                     ""                        ← 第 0 层：还没做任何选择
          ┌───────────┼───────────┐
        "a"          "b"          "c"           ← 第 1 层：为 digits[0]='2' 选字母
      ┌──┼──┐      ┌──┼──┐      ┌──┼──┐
   "ad" "ae" "af" "bd" "be" "bf" "cd" "ce" "cf" ← 第 2 层：为 digits[1]='3' 选字母
     ★    ★    ★    ★    ★    ★    ★    ★    ★  ← 叶子：i == 2，一条完整答案
```

看这棵树，题目里所有量都对上了：

| 树上的概念 | 这道题里是什么 |
| ---------- | -------------- |
| 树的深度 | `digits` 的长度 |
| 第 `i` 层有多少叉 | `digits[i]` 对应的字母个数（3 或 4） |
| 一个节点 | 一个**前缀**，比如 `"ae"` 是「前两位定了 a、e」 |
| 一条从根到叶的路径 | 一个**完整答案** |
| 叶子个数 | 答案个数 = 各层分支数**相乘** |

「各层相乘」这件事很关键：`digits` 长度是 4 时，`"9999"` 有 `4⁴ = 256` 个答案，而 `"2345"` 只有 `3⁴ = 81` 个。**答案规模是输入长度的指数级**——所以任何「把所有组合都列出来」的题，复杂度注定是指数的，这不是解法没写好，是题目本身的要求。

### 回溯的三个动作

`backtrack` 函数体去掉边界判断后，核心就是循环里的三行：

| 动作 | 代码 | 在树上对应什么 |
| ---- | ---- | -------------- |
| 做选择 | `combination.push_back(letter)` | 从分叉口顺着一条边往下走一层 |
| 递归 | `backtrack(..., i + 1, ...)` | 进入子树的根，继续往下走 |
| 撤销选择 | `combination.pop_back()` | 从那条边**退回**分叉口，换下一条边 |

而「走到底」由边界判断负责：

```cpp
if (i == digits.length()) {
    combinations.push_back(combination);   // 此刻 combination 正是一条完整路径
    return;                                // 触底，往回走
}
```

### 一句话说出它为什么必须成对：不变量

上面三行里，`push_back` 和 `pop_back` 一个在前、一个在后，中间夹着递归——这个结构不是凑出来的，它由下面这条**不变量**决定：

> **`backtrack(i)` 进入时，`combination` 恰好是决策树上「从根走到当前节点」这条路径；
> `backtrack(i)` 返回时，它必须恢复成和进入时一模一样。**

这条不变量一立起来，前面那些写法就全都是它的推论：

- **为什么 `push` / `pop` 必须成对**：进入子节点前加了字符，回来时就得把它删掉，否则违反「返回时恢复原样」。
- **为什么触底时可以直接记录 `combination`**：因为按不变量，此刻它**正好等于**一条从根到叶的路径，不需要额外拼装。
- **为什么兄弟分支互不干扰**：`i = 1` 轮到 `'b'` 的时候，缓冲区已经被上一个兄弟 `'a'` 完整地还原干净了。

### 撤销不是「清理垃圾」，是「恢复现场」

这里有一个容易滑过去的点：**`combination` 是所有分支共用的一份缓冲区**（传引用，全程只有一个）。共享是为了省复制，但共享有代价——**你改了什么，别人都会看见**。所以「改坏」之后必须自己复原。

用实测的调用轨迹看 `digits = "23"` 最直观（只截了 `'a'` 那支）：

```
↓ backtrack(i=0)  进入时 combination=""
  push('a') → "a"
  ↓ backtrack(i=1)  进入时 combination="a"
    push('d') → "ad"
    ↓ backtrack(i=2)  进入时 combination="ad"
    ★ 触底，记录 "ad"
    pop()    → "a"     （回到进入时的状态）
    push('e') → "ae"
    ↓ backtrack(i=2)  进入时 combination="ae"
    ★ 触底，记录 "ae"
    pop()    → "a"     （回到进入时的状态）
    ...
  ↑ backtrack(i=1) 返回，combination="a"
  pop()    → ""      （回到进入时的状态）
  push('b') → "b"
  ...
↑ backtrack(i=0) 返回，combination=""
```

三次 `pop()` 之后，缓冲区都**精确地**回到了 `push` 之前的样子——这就是「回溯」这个名字的字面意思。整趟跑完，`combination` 复原成 `""`，而答案已经攒了 9 个。**干活的那个缓冲区最后是空的，成果全在 `combinations` 里。**

### 递归不等于回溯

初学者容易把「递归」和「回溯」当成一回事。它们的区别只有一条：**改过的状态要不要还原**。

| 题目 | 递归里改了什么 | 还原吗 | 是回溯吗 |
| ---- | -------------- | ------ | -------- |
| [226 翻转二叉树](0226-invert-binary-tree.md) | 交换左右孩子 | 不还原 | 否——交换**本身就是答案** |
| [200 岛屿数量](0200-number-of-islands.md) | `grid[r][c] = '0'` | 不还原 | 否——淹掉这座岛**就是目的** |
| 17 本题 | `combination` 增删字符 | **必须还原** | **是**——它只是一条临时路径 |

判别标准很好用：**如果中途改的那个东西「留着也算数」，那它是普通 DFS；如果它「只是过程中的脚手架、最后不该留下来」，那就是回溯，必须撤销。**

这也顺带解释了为什么回溯题的结果都存在另开的容器里（本题的 `combinations`）：缓冲区会被反复改回原样，留不住成果。

### 每个参数各司其职

看 `backtrack` 的四个参数，它们其实是四种不同角色的东西：

| 参数 | 角色 | 传参方式 | 全程变化 |
| ---- | ---- | -------- | -------- |
| `combinations` | 结果集 | `&` | 只增不减，从不回退 |
| `phoneMap` / `digits` | 只读输入 | `const &` | 从不改变 |
| `i` | 层号（只读游标） | 值 | 每层不同，但每个节点各持一份，不会互相影响 |
| `combination` | 当前路径（可变状态） | `&` | **全程只有一份**，靠 push / pop 前进和后退 |

值得注意的是 `i`：它为什么要用「下标」而不是 `digits.substr(1)` 这种「截短的剩余串」？因为 `substr` 每次都要**复制**一份字符串，而 `i` 是个 O(1) 的只读游标。这跟 `combination` 传引用是同一个思路——**能共享就别复制**。回溯的整个设计取向就是：状态只维护一份，靠前进 / 后退复用，而不是每一层都拷贝一份新的。

## 解题步骤

### 思路一：n 重循环（想清楚最笨的办法）

固定长度的话，这题的暴力解就是嵌套循环——`digits.length() == 2` 时两层：

```cpp
for (char c1 : PHONE.at(digits[0]))
    for (char c2 : PHONE.at(digits[1]))
        ans.push_back(string{c1, c2});
```

`digits.length() == 4` 就写四层。长度变了，循环的层数就得跟着变，而**循环层数在编译期是写死的**——这就是暴力解的死穴。

想通这一点，「递归」在这里的作用就清楚了：

> **递归就是「层数不定的循环嵌套」。** 循环的层数由输入长度决定，那就把「再套一层循环」这件事交给函数调用自己完成。

而每次调用返回时要做的那件「收尾工作」，就是回溯的撤销。

### 思路二：按层做笛卡尔积（不用回溯也能过）

换个方向，一层一层往外扩：从 `[""]` 出发，每读一位数字，就把当前所有前缀和该数字的每个字母拼一遍。

```cpp
vector<string> letterCombinations(string digits) {
    vector<string> ans;
    if (digits.empty()) return ans;
    ans.push_back("");
    for (char d : digits) {
        vector<string> next;
        for (const string& prefix : ans)
            for (char c : PHONE.at(d))
                next.push_back(prefix + c);
        ans.swap(next);
    }
    return ans;
}
```

这个思路完全正确，而且更接近「笛卡尔积」的本来面目。但它和回溯有个本质差别：

> **它是「宽度优先」，并且每一层都把路径完整复制了一份。** 走到第 `k` 层时，内存里同时躺着 `4ᵏ` 个长度为 `k` 的字符串；而回溯全程只有一个缓冲区，长度不超过 `n`。

`digits` 最长 4 位时这点差别无所谓，但它是理解回溯**为什么存在**的关键：回溯用「一份状态 + 撤销」换掉了「每层复制一份状态」。

### 思路三：回溯（核心解法）

按决策树走：第 `i` 层为 `digits[i]` 选一个字母，选完往下走，回来时撤销。

```cpp
class Solution {
public:
    vector<string> letterCombinations(string digits) {
        vector<string> combinations;
        if (digits.empty()) {
            return combinations;
        }
        unordered_map<char, string> phoneMap {
            {'2', "abc"},
            {'3', "def"},
            {'4', "ghi"},
            {'5', "jkl"},
            {'6', "mno"},
            {'7', "pqrs"},
            {'8', "tuv"},
            {'9', "wxyz"}
        };
        string combination;
        backtrack(combinations, phoneMap, digits, 0, combination);
        return combinations;
    }

    void backtrack(vector<string>& combinations, const unordered_map<char, string>& phoneMap,
                   const string& digits, int i, string& combination) {
        if (i == digits.length()) {          // 触底：一条完整路径到手
            combinations.push_back(combination);
        } else {
            char digit = digits[i];
            const string& letters = phoneMap.at(digit);
            for (const char& letter : letters) {
                combination.push_back(letter);        // 做选择
                backtrack(combinations, phoneMap, digits, i+1, combination);   // 递归
                combination.pop_back();               // 撤销选择
            }
        }
    }
};
```

几个细节：

- `phoneMap` 是 `const` 引用，取字母必须用 `.at(digit)`，**不能用 `phoneMap[digit]`**——`operator[]` 有「不存在就插入」的语义，`const` 对象上根本编译不过。
- `i == digits.length()` 是 `int` 和 `size_t` 比较，会有符号性警告。要消掉就写成 `i == (int)digits.length()`，或者把 `i` 声明成 `size_t`。
- C++ 里其实不必用哈希表：`static const string TABLE[8] = {"abc", "def", ...};` 用 `TABLE[digit - '2']` 直接索引更快，也省掉一次哈希。本题数据量小，无所谓，知道有这条就够了。

### 代码（Python）

```python
class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:
            return []

        phone = {
            '2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
            '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz',
        }
        combinations = []
        combination = []

        def backtrack(i: int) -> None:
            if i == len(digits):
                combinations.append(''.join(combination))
                return
            for letter in phone[digits[i]]:
                combination.append(letter)      # 做选择
                backtrack(i + 1)                # 递归
                combination.pop()               # 撤销选择

        backtrack(0)
        return combinations
```

Python 里用 `list` 而不是 `str` 当缓冲区：`str` 不可变，每层 `combination + letter` 都会新建一个字符串，等于退化成思路二的「按值复制」。`list` 的 `append` / `pop` 才是真正的原地增删。

### 代码（Python）：传副本的写法

既然说「传副本就不需要撤销」，那就把那个版本也写出来对照。它把路径作为**参数**传下去，每层各持一份：

```python
def backtrack(i: int, path: str) -> None:
    if i == len(digits):
        combinations.append(path)
        return
    for letter in phone[digits[i]]:
        backtrack(i + 1, path + letter)     # 没有 append，也没有 pop
```

读起来更短、更不容易写错，代价是每一层都新建一个字符串。两种写法都对，**但不能混着理解**：

| 缓冲区怎么传 | 要不要撤销 | 状态有几份 |
| ------------ | ---------- | ---------- |
| 传引用 / 共用一份（本题主解法） | **必须**配对撤销 | 1 份 |
| 传值 / 每层新建 | 不需要 | 每个节点 1 份 |

最危险的组合是「共用一份却忘了撤销」，下一页有实测。

### 复杂度分析

设答案为 `M` 个——`M = 3ᵃ × 4ᵇ`，其中 `a` 是映射到 3 个字母的数字个数（2、3、4、5、6、8），`b` 是映射到 4 个字母的（7、9）。

- **时间复杂度**：`O(n · M)`。递归树的总节点数约为 `M · b/(b-1)`（实测：`"234"` 是 40 个节点 / 27 个叶子，`"9999"` 是 341 / 256），走完是 `O(M)`；每个叶子记录答案时要复制一份长度为 `n` 的字符串，所以再乘一个 `n`。
- **空间复杂度**：`O(n)`（不计输出）。递归深度最多 `n` 层，缓冲区 `combination` 全程只有一份、长度不超过 `n`。
- 答案本身占 `O(n · M)`，这是题目要求输出所有组合决定的，任何解法都躲不掉。

## 小结

### 易错点

**① 忘了 `pop_back()`——答案个数还是对的，内容全错**

这是最阴的一个。删掉那一行再跑 `digits = "23"`：

```
个数=9（应为 9）
[ad, ade, adef, adefbd, adefbde, adefbdef, adefbdefcd, adefbdefcde, adefbdefcdef]
```

**答案个数依然是 9**——因为叶子个数只由树的结构（每位数字有多少个字母）决定，跟缓冲区没关系。但每条路径都挂着前面所有兄弟留下的残渣，而且残渣还在累积。第一个答案 `"ad"` 看着是对的，往后越错越离谱。

这里的教训是：**「答案个数对」这个自检指标抓不到这个 bug**，必须比对内容。我拿它对拍过：这个错误版本在 `digits = "23"` 上返回的 9 个字符串里，只有第 1 个是对的。

**② 忘了 `digits.empty()` 特判——返回 `[""]` 而不是 `[]`**

不特判的话，`digits = ""` 时 `i = 0` 直接等于 `length()`，第一件事就是 `push_back("")`：

```
没有特判：size=1，唯一的元素是空串 ""
有特判  ：size=0（空 vector，元素个数为 0）
```

`[""]` 和 `[]` 打印出来都是 `[]`，肉眼很难分辨，但判题用的是元素个数，直接判错。**空输入是回溯题最常见的边界**：它恰好满足「已经走到终点」的条件，会多产出一个不该有的空答案。

**③ 传引用不撤销 / 传值又去撤销**

两种传参方式必须配套（见上表）。传引用忘撤销（第 ① 条）会出错；反过来传值还写 `pop_back` 不会出错，只是白写——改的是即将被丢弃的副本。真正要避免的是**脑子里把两种模型混起来**。

**④ 用 `phoneMap[digit]` 取字母**

`phoneMap` 是 `const` 引用，`operator[]` 在上头编译不过；就算去掉 `const`，它在键不存在时也会**静默插入一个空串**并把问题推到后面。

**⑤ 触底条件写错成 `combination.size() == digits.length()`**

本题里它和 `i == digits.length()` 恰好等价（每层正好加一个字符），所以不容易发现。但这假设了「层数 == 路径长度」，一旦题目变成「一位数字可能对应 0 个字母」或者「一层要选两个字符」，这行就悄悄错了。**用层号判断层级，是更稳的写法。**

### 可迁移的套路

**回溯模板**（这道题的骨架，也是 46 / 78 / 39 那些题的骨架）：

```
void backtrack(层号 i, 可变状态 &path) {
    if (到达终点) {          // 1. 结束条件
        结果集.push_back(path);
        return;
    }
    for (每个可选的值 choice : 这一层的选择列表) {
        path.push_back(choice);     // 2. 做选择
        backtrack(i + 1, path);     // 3. 递归
        path.pop_back();            // 4. 撤销选择（与第 2 步严格成对）
    }
}
```

套用到新题上，只需要回答三个问题：

1. **决策树的每一层是什么？** —— 本题是「第 `i` 位数字选哪个字母」；全排列是「第 `i` 个位置放哪个数」；子集是「第 `i` 个元素选 or 不选」。
2. **什么时候算走到终点？** —— 本题是 `i == digits.length()`；全排列是 `i == nums.size()`；子集是每个元素都决定完了。
3. **中途改了什么状态、怎么还原？** —— 本题是 `combination` 的增删；全排列是 `used[]` 数组的置位与复位；N 皇后是「这一列 / 两条对角线被占用」的置位与复位。

第 3 条是回溯区别于普通 DFS 的地方，也是唯一容易写错的地方。写完 `push_back`，立刻在脑子里把对应的 `pop_back` 也写上——**成对写，别回头补。**

**自检方法**：在 `backtrack` 返回前断言缓冲区已经复原（本题就是检查 `combination` 等于进入时的内容）。不变量一旦被破坏，会立刻炸在出错的那一层，而不是等到最后答案对不上还要倒推。

### 同族题目

同一套「决策树 + 做选择 / 撤销选择」的骨架，区别只在选择列表和终点判断：

| 题目 | 每一层选什么 | 撤销的是什么 |
| ---- | ------------ | ------------ |
| 17 电话号码的字母组合 | 这一位数字对应哪个字母（本题） | 路径末尾的字符 |
| 78 子集 | 第 `i` 个元素：要 or 不要 | 路径末尾的元素 |
| 46 全排列 | 还没用过的哪个数 | 路径末尾 + `used[]` 的复位 |
| 39 组合总和 | 下一个数取几（可重复取） | 路径末尾 + 剩余和 |
| 22 括号生成 | 这一位放 `(` 还是 `)` | 路径末尾（可用数靠计数恢复） |
| 79 单词搜索 | 当前位置往四个方向的哪个走 | 路径末尾 + 棋盘格子的复原 |
| 131 分割回文串 | 下一个回文子串切多长 | 路径末尾的整个子串 |
| 51 N 皇后 | 第 `i` 行皇后放哪一列 | 列 / 两条对角线的占用标记 |

其中 **79 单词搜索**（把走过的格子临时标记成 `visited`，回溯时再改回来）是最能印证「回溯 = 改完要还原」的一道：它和 200 岛屿数量的代码长得几乎一样，唯一区别就是**那个标记要不要撤销**——200 的「淹掉」是答案的一部分，79 的「标记」只是路上的脚手架。
