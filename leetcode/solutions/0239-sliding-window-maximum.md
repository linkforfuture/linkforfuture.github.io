## 题目

给你一个整数数组 `nums`，有一个大小为 `k` 的**滑动窗口**从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

返回**滑动窗口中的最大值**。

| 输入 | 输出 |
| ---- | ---- |
| `nums = [1,3,-1,-3,5,3,6,7]`，`k = 3` | `[3,3,5,5,6,7]` |

窗口逐次滑动的情况：

| 窗口 | 内容 | 最大值 |
| ---- | ---- | ------ |
| 1 | `[1  3  -1] -3  5  3  6  7` | 3 |
| 2 | `1 [3  -1  -3] 5  3  6  7` | 3 |
| 3 | `1  3 [-1  -3  5] 3  6  7` | 5 |
| 4 | `1  3  -1 [-3  5  3] 6  7` | 5 |
| 5 | `1  3  -1  -3 [5  3  6] 7` | 6 |
| 6 | `1  3  -1  -3  5 [3  6  7]` | 7 |

## 我的理解

### 暴力解法浪费在哪

最直接的做法是：每次窗口右移，就重新扫描窗口内的 `k` 个数取最大值。`n - k + 1` 个窗口 × 每个扫 `k` 次 = `O(nk)`。

但仔细想想，窗口右移一次，**只淘汰了最左边一个数、只新增了最右边一个数**。剩下的 `k - 2` 个数原封不动，却被重新看了一遍。这就是浪费的来源。

### 一个数什么时候「永远没用了」

要让「不重扫」成为可能，得能判定：某个数从今往后还有没有机会当最大值。答案是它只在两种情况下彻底出局：

1. **被压制**：来了一个比它更大、而且比它更晚过期的数。那它既比不过人家，又比人家先走，永远轮不到它。
2. **过期**：它滑出了窗口左边界。

把这两种情况都及时清理掉，剩下的就都是「还有机会」的候选人。而其中**值最大的那个**，就是当前窗口的答案。

### 于是就有了单调队列

用一个 `deque` 存**下标**（不是值），并维持一条纪律：**从队首到队尾，对应的值严格递减**。这样：

- **队首 = 当前窗口最大值**，取答案 O(1)；
- 新元素从**队尾**进来，因为它是「最不可能赢但活得最久」的那个；
- 被压制的元素一定堆在**队尾**——新元素在时间维度上必然最新，它只能压过那些「值也不如它」的元素，而那些恰好都在尾部。

### 我踩过的坑

- **把 `deque` 当成会自动排序的容器。** 它不是。`std::deque` 就是个两头都能 O(1) 进出的数组，`push_back` 只管往里扔，不做任何比较。那条「递减」的纪律是**代码里的 `while` 循环手动维护出来的**，容器完全不知道里面的值是有序的。这个误解不破除，整段代码都看不懂。
- **存值而不是存下标。** 存值就没法判断过期了——值会重复，下标才是唯一身份。
- 以为那个嵌套的 `while` 会让复杂度变成 `O(n²)`。不会，见下面的复杂度分析。

**一句话概括：维护一个「候选人队列」，队首到队尾的值递减；每来一个新元素，先把队尾那些「又旧又小、彻底没戏」的弹掉，再把自己放进队尾，最后把滑出窗口的队首弹掉——此时队首就是窗口最大值。**

## 解题步骤

### 思路一：暴力（先把最笨的办法想清楚）

枚举每个窗口，内部再扫一遍取最大值。

```cpp
vector<int> maxSlidingWindow(vector<int>& nums, int k) {
    vector<int> result;
    for (int i = 0; i + k <= (int)nums.size(); ++i) {
        int mx = nums[i];
        for (int j = i + 1; j < i + k; ++j)
            mx = max(mx, nums[j]);
        result.push_back(mx);
    }
    return result;
}
```

- 窗口数 `n - k + 1`，每个窗口扫 `k` 次；
- 总复杂度 `O(nk)`，`n = 10⁵` 时就超时了。

这一步的价值在于确认了「答案就是每个窗口内的最大值」，后面要做的只是**别重复劳动**。

### 思路二：单调队列（核心解法）

四步，一一对应前面说的两种淘汰：

| 步骤 | 代码 | 在解决什么 |
| ---- | ---- | ---------- |
| ① 队尾淘汰 | `while nums[dq.back()] <= nums[i]` → `pop_back` | 值维度：又旧又小的被新元素**永久压制** |
| ② 自己入队 | `dq.push_back(i)` | 存下标，供步骤③判断过期 |
| ③ 队首过期 | `if dq.front() <= i - k` → `pop_front` | 时间维度：滑出窗口 `[i-k+1, i]` 的左边界 |
| ④ 记录答案 | `if i >= k-1` → `nums[dq.front()]` | 队首即最大值 |

两个容易被追问的细节：

- **步骤③为什么用 `if` 而不是 `while`？** 因为下标是递增入队的，队列内部下标一定从小到大排列，队首就是**最旧**的那个。它要是没过期，第二个更不可能过期——所以最多弹一个。
- **步骤①为什么用 `<=` 而不是 `<`？** 把相等的旧元素也弹掉，让同一值只保留最新的下标，更晚过期、更耐用。两种写法结果都对，这只是习惯上的更优解。

### 代码（C++）

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        std::deque<int> dq;               // 存下标，对应值严格递减
        std::vector<int> result;

        for (int i = 0; i < (int)nums.size(); ++i) {
            // 1. 队尾比 nums[i] 小的都没机会成为最大值，弹出
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            dq.push_back(i);

            // 2. 队首滑出窗口 [i-k+1, i]，弹出
            if (dq.front() <= i - k) {
                dq.pop_front();
            }

            // 3. 窗口形成后，队首即最大值
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        return result;
    }
};
```

注意步骤②和③的顺序：**先入队再判过期**，队列在步骤③时一定非空，所以访问 `dq.front()` 不需要额外判空。

### 代码（Python）

```python
from collections import deque

def maxSlidingWindow(nums: list[int], k: int) -> list[int]:
    dq = deque()                      # 存下标，对应值严格递减
    result = []

    for i, x in enumerate(nums):
        # 1. 队尾比 x 小的都没机会成为最大值，弹出
        while dq and nums[dq[-1]] <= x:
            dq.pop()
        dq.append(i)

        # 2. 队首滑出窗口 [i-k+1, i]，弹出
        if dq[0] <= i - k:
            dq.popleft()

        # 3. 窗口形成后，队首即最大值
        if i >= k - 1:
            result.append(nums[dq[0]])

    return result
```

### 复杂度分析

- **时间复杂度**：`O(n)`。关键在于**每个下标一生最多入队 1 次、出队 1 次**，所以那个嵌套 `while` 的循环体在整个算法一生中最多执行 `n` 次——不是每次迭代 `n` 次。连 `while` 的条件判断加起来也不超过 `2n`。均摊到每次迭代是 `O(1)`。
- **空间复杂度**：`O(k)`。队列里最多同时存在 `k` 个下标（窗口内每个元素都在队列里是上界）。

> 补充一句：单次迭代**确实可能很贵**。比如 `nums = [5,4,3,2,1,100]`、`k = 3`，前 5 次一个都不弹，`i = 5` 时一次弹光 5 个。但那 5 次弹出的代价是前面 5 次入队时「预付」的，总账不变——这正是摊还分析的意思。

## 小结

### 判别法：什么时候该想到单调队列

四个条件同时成立就该警觉：

1. 有**滑动窗口**，或任何固定长度的连续区间；
2. 求区间内的 **max / min**（求 sum 请用前缀和）；
3. 窗口**单向移动**，从前往后不回退；
4. 需要 `O(n)`，不接受 `O(n log n)`。

本质判据只有一句：**存在支配关系，且被支配者能被永久删除。**

### 变形：改一个维度就是另一道题

| 改动 | 得到什么 |
| ---- | -------- |
| 比较方向 `<=` 改成 `>=` | 滑动窗口**最小值** |
| 去掉**时间维**淘汰（步骤③） | **单调栈**——解决「下一个更大元素」 |
| 去掉**值维**淘汰（步骤①） | 普通队列——滑动平均 / 定长区间和 |
| 同时挂两个队列（一增一减） | 同时维护区间的 max 和 min（如 1438） |
| 存的不是 `nums[j]` 而是 `dp[j] + w(j)` | **单调队列优化 DP** |

### 最有价值的迁移：单调队列优化 DP

一大类 DP 的形状是 `dp[i] = max{ dp[j] + w(j) }, j ∈ [i-k, i-1]`。把窗口里装的 `nums[j]` **整个换成 `dp[j] + w(j)`**，代码结构一字不改，转移从 `O(k)` 降到 `O(1)`，整体从 `O(nk)` 降到 `O(n)`。

- 1696 跳跃游戏 VI（`dp[i] = nums[i] + max(dp[j])`，最标准的模板）
- 1425 带限制的子序列和、1499 满足不等式的最大值、1687 从仓库到码头运输箱子
- 多重背包的单调队列优化（竞赛经典）

### 易错点

- 存下标，别存值。
- 步骤②③的顺序别调换，现在的顺序让步骤③免去判空。
- 别用 `vector`：它的 `pop_front()` 要整体前移，是 `O(k)`，总复杂度直接退化成 `O(nk)`。
- 官方样例 `[1,3,-1,-3,5,3,6,7]` 有个巧合：**步骤③一次都不会触发**，因为最大值总在过期前就被更大的顶掉了。想真正看到「队首滑出」，换成 `[7,2,4,6,3,5,1,8]` 试试——配套图解用的就是这个数组。
