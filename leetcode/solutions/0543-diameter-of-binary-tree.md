# 543. 二叉树的直径

> **难度**：简单　**标签**：树 · 递归 · 深度优先搜索
> **链接**：[LeetCode 543](https://leetcode.cn/problems/diameter-of-binary-tree/)

理解这道题，要先分清递归中两个不同的结果：`ans` 记录已经找到的最长路径，`depth()` 则向父节点返回一条最长的向下链。因此，更新答案时使用 `L + R + 1`，返回深度时使用 `max(L, R) + 1`。

## 题目

给定一棵二叉树的根节点 `root`，返回它的直径。直径是任意两个节点之间最长路径的**边数**，这条路径不一定经过整棵树的根节点。

这里讨论的是**直径**。宽度描述树在某一层的横向规模，与本题的最长路径不同。

例如：

```text
    1
   / \
  2   3
 / \
4   5
```

最长路径可以是 `4 → 2 → 1 → 3`，包含 4 个节点、3 条边，因此返回 `3`。

## 代码实现

保留按节点数计算深度和路径长度的写法，最后再转换为边数：

```cpp
class Solution {
public:
    int depth(TreeNode* root, int& ans) {
        if (root == nullptr) {
            return 0;
        }

        int L = depth(root->left, ans);
        int R = depth(root->right, ans);

        // 以当前节点为两侧分支交汇点，尝试更新最长路径的节点数。
        ans = max(ans, L + R + 1);

        // 返回从当前节点出发的最长向下链，供父节点继续连接。
        return max(L, R) + 1;
    }

    int diameterOfBinaryTree(TreeNode* root) {
        int ans = 1;
        depth(root, ans);
        return ans - 1;
    }
};
```

## 先明确 L 和 R 的含义

先给递归函数约定一个明确的含义：

> `depth(x, ans)` 返回以 `x` 为根的子树的最大深度，按节点数计算；处理这棵子树时，同时更新共享的 `ans`。

因此，空树深度为 `0`，叶子节点深度为 `1`。每次递归返回后：

- `L` 是左子树的最大深度，**不包含当前节点**。
- `R` 是右子树的最大深度，**不包含当前节点**。

从当前节点往下看，这个量也常被称为子树的高度。本篇沿用代码中的 `depth` 命名。

例如：

```text
        A
       / \
      B   C
     /     \
    D       E
   /
  F
```

在节点 `A` 处，左子树最长的向下链是 `B → D → F`，所以 `L = 3`；右子树最长的向下链是 `C → E`，所以 `R = 2`。当前节点 `A` 还没有被计算进去。

## 为什么更新答案用 L + R + 1

固定当前节点 `A`，尝试把左右两侧的路径拼起来：

```text
F → D → B → A → C → E
```

这条路径由三段组成：

| 路径部分 | 节点数 |
| --- | --- |
| 左子树中最长的向下链，反向走回当前节点 | `L` |
| 当前节点自己 | `1` |
| 右子树中最长的向下链 | `R` |

左右子树互不重叠，所以两段链可以独立选择，各取最长，总节点数就是 `L + R + 1`。在这个例子中是 `3 + 2 + 1 = 6`。

准确地说，`L + R + 1` 是**以当前节点为两侧分支交汇点的最长路径的节点数**，不能直接认定它就是整棵树的直径。还需要和其他节点处找到的路径比较：

```cpp
ans = max(ans, L + R + 1);
```

如果某一侧为空，对应深度就是 `0`；如果两侧都为空，候选路径就只有当前节点，公式仍然成立。

## 为什么返回深度用 max(L, R) + 1

父节点需要的是**从当前节点出发，向下走的一条最长链**。对于上面的 `A`，只能选择：

- `A → B → D → F`，包含 4 个节点。
- `A → C → E`，包含 3 个节点。

取两者较长的一条，再把它交给父节点，因此返回：

```cpp
return max(L, R) + 1;
```

`max(L, R)` 表示选择更深的一侧，`+ 1` 表示加上当前节点。

### 为什么不能把左右两侧一起返回

假设 `A` 上面还有父节点 `P`：

```text
        P
        |
        A
       / \
      B   C
```

如果一条路径已经通过 `P → A` 接入这里，接下来只能往 `B` 或 `C` 的一个方向继续。若还想把另一侧也走完，就必须回到 `A`，重复经过节点。

树中的简单路径不能重复节点，也不能在一个节点处分成三个方向。因此，左右拼接的结果可以在当前节点处作为候选答案，但无法再作为一条向下链交给父节点。

| 当前层的任务 | 可以使用的分支 | 计算方式 |
| --- | --- | --- |
| 尝试更新整棵树的最长路径 | 左右两侧都可以使用 | `L + R + 1` |
| 返回可供父节点继续连接的深度 | 只能选择一侧 | `max(L, R) + 1` |

## 为什么每个节点都要更新 ans

最长路径可能完全位于某棵子树内部。例如：

```text
        1
       /
      2
     / \
    3   4
   /     \
  5       6
```

在节点 `2` 处，`L = 2`、`R = 2`，可以拼出：

```text
5 → 3 → 2 → 4 → 6
```

这条路径包含 5 个节点、4 条边。但在整棵树的根节点 `1` 处，`L = 3`、`R = 0`，候选路径只有 4 个节点，例如 `1 → 2 → 3 → 5`。

因此，只在整棵树的根节点计算一次会漏掉答案。递归必须在**每个节点**处检查左右两条链能拼出多长的路径。

### 为什么这样不会漏掉最长路径

任意一条路径都有一个最靠近树根的节点，它也是两个端点的最近公共祖先。在这个节点处，路径可以拆成左侧的一条向下链、当前节点、右侧的一条向下链；某一侧允许为空。

递归遍历所有节点，就一定会检查到最长路径的这个交汇点。而这里选择的左右最深链，长度不会小于原路径的两段；拼出的结果本身又是一条合法路径，所以能找到全局最优解。

## 手动跟踪递归返回过程

仍使用上面的 6 个节点。函数先递归左子树，再递归右子树，最后计算当前层，属于**后序遍历**。下表省略返回 `0` 的空指针调用，按非空节点实际完成计算的顺序排列。

`ans` 初值为 `1`，并通过 `int&` 引用传递；所有递归层更新的是同一个变量。

表中「候选」为 `L + R + 1`，「ans」为更新后的值，「深度」为返回给父节点的 `max(L, R) + 1`。

| 节点 | L | R | 候选 | ans | 深度 |
| --- | --- | --- | --- | --- | --- |
| `5` | 0 | 0 | 1 | 1 | 1 |
| `3` | 1 | 0 | 2 | 2 | 2 |
| `6` | 0 | 0 | 1 | 2 | 1 |
| `4` | 0 | 1 | 2 | 2 | 2 |
| `2` | 2 | 2 | 5 | 5 | 3 |
| `1` | 3 | 0 | 4 | 5 | 4 |

最关键的是节点 `2` 这一行：它用左右两条链得到 5 个节点的候选路径，但只向父节点返回深度 `3`。到节点 `1` 时，候选路径变短，`max` 会保留已经找到的 `ans = 5`。

因此，最外层 `depth(root, ans)` 的返回值是整棵树的深度 `4`，真正要的直径则保存在 `ans` 中。最终返回 `ans - 1 = 4` 条边。

## 节点数与边数

当前实现始终用节点数计算深度。对于非空路径，节点数比边数多 `1`：

```text
候选路径节点数 = L + R + 1
候选路径边数   = L + R
```

所以，当前实现先记录最长路径的节点数，最后统一执行 `ans - 1`。也可以直接按边数维护答案，但那时应将 `ans` 初始化为 `0`、更新为 `max(ans, L + R)`，最后直接返回 `ans`，三处要配套调整。

对于非空树，`ans = 1` 对应至少包含一个节点的路径。当前写法也能处理空指针输入：`depth(nullptr, ans)` 直接返回 `0`，`ans` 保持初值 `1`，最后得到 `0`。这是初始化带来的兼容结果，不能据此把空树深度也算成 `1`。

| 情况 | 深度 | 直径边数 | 检查点 |
| --- | --- | --- | --- |
| 空树 | 0 | 0 | 空指针直接返回，不访问孩子 |
| 单节点 | 1 | 0 | `L = R = 0`，只有节点，没有边 |
| 两个节点相连 | 2 | 1 | 某一侧为空时公式仍成立 |
| 4 个节点组成单链 | 4 | 3 | 深度按节点数，直径按边数 |
| 上面的 6 节点示例 | 4 | 4 | 最长路径完全位于左子树内部 |

## 复杂度与易错点

- **时间复杂度**：`O(n)`。每个节点访问一次，在当前层只做常数次运算。
- **空间复杂度**：`O(h)`。递归栈的最大深度由树高决定；平衡树为 `O(log n)`，退化成链时为 `O(n)`。

容易混淆的地方有三个：

1. 把当前节点处的候选路径当成整棵树的直径。需要遍历所有节点，并用 `ans` 保留最大值。
2. 把 `L + R + 1` 作为递归返回值。这会把两条分支当成一条链交给父节点，破坏深度的含义。
3. 混用节点数与边数。当前 `depth()` 按节点数计算，最终答案只减一次 `1`。

记住这两行各自服务的目标：**左右都用，尝试更新最长路径；左右选大，返回可继续连接的深度。**
