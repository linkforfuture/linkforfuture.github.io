## 题目

给你一棵二叉树的根节点 `root`，翻转这棵二叉树，并返回其根节点。翻转的含义是：树里**每一个节点**的左右孩子都互换位置。

**示例 1**

```
输入：root = [4,2,7,1,3,6,9]
输出：[4,7,2,9,6,3,1]
```

**示例 2**

```
输入：root = [2,1,3]
输出：[2,3,1]
```

**示例 3**

```
输入：root = []
输出：[]
```

**提示**

- 树中节点数目范围在 `[0, 100]` 内
- `-100 <= Node.val <= 100`

## 我的理解

### 卡住的点

代码只有 7 行，但盯着看的时候脑子里没有画面。问题出在想同时跟踪所有层：`invertTree(root->left)` 里面又要调用 `invertTree`，那里面又要调用……这条链在脑子里永远展开不完，于是「逻辑」就散了。

后来明白，**递归不是靠展开来理解的，是靠契约来理解的**。

### 破局：把递归当成一份契约

先给这个函数写一句合同：

> `invertTree(x)`：给我任何一棵子树的根（哪怕是空指针），我还你**同一棵树**，但里面每个节点的左右孩子都已经互换。

有了这句合同，读代码时就把每次递归调用当成一个**必定兑现的黑盒**，不去想它内部怎么实现。于是整段代码只剩三个问题：

| 问题 | 答案 | 对应代码 |
| ---- | ---- | -------- |
| 什么时候不用干活？ | 空树没有孩子可换，原样返回 | 第 4–5 行 |
| 怎么把问题变小？ | 把左子树、右子树分别整棵交出去 | 第 7–8 行 |
| 拿到结果后这一层做什么？ | 把两棵「已翻好」的子树对调挂回，再交还 | 第 9–11 行 |

### 代码有两个方向

- **下去（第 7–8 行）**：只拆不改。把子任务派出去，然后**停在原地等结果**。下降路上没有任何节点被修改。
- **上来（第 9–11 行）**：组装交换。两棵成品到手，互换挂回，再 `return root`。

所以**翻转动作 100% 发生在回程**，整棵树是自底向上翻好的：叶子最先完成，根节点最后交换。这也是为什么「最先被调用的根节点，反而最后才交换」。

### 局部变量 left / right 的作用

它们相当于两只手：先把两棵成品子树都**拿稳**，再去改 `root` 的指针。因为第 9 行一旦执行，`root->left` 里原来的指针就被覆盖了，不先存下来就再也找不回来。

**一句话概括：每个节点只做一件小事——等左右两棵子树各自翻好，把两根孩子指针对调，然后把自己交还上一层；空树直接返回，这就是递归的底。**

## 解题步骤

### 思路一：迭代（先把「遍历每个节点」这件事想清楚）

翻转的定义拆开看，其实就是「**访问每个节点一次，交换它的两个孩子**」。那么任何一种遍历都能做到，用队列做 BFS 最直白：

```cpp
TreeNode* invertTree(TreeNode* root) {
    if (root == nullptr) return nullptr;
    std::queue<TreeNode*> q;
    q.push(root);
    while (!q.empty()) {
        TreeNode* x = q.front(); q.pop();
        std::swap(x->left, x->right);
        if (x->left)  q.push(x->left);
        if (x->right) q.push(x->right);
    }
    return root;
}
```

这一步的价值在于确认了「答案 = 每个节点各交换一次孩子」，后面要做的只是**换一种方式遍历**。

### 思路二：递归（核心解法）

递归版把「遍历所有节点」这件事交给调用栈代劳。执行顺序是**后序位置**做交换：

| 步骤 | 代码 | 在做什么 |
| ---- | ---- | -------- |
| ① 刹车 | `if (root == nullptr) return nullptr;` | 空树原样返回，递归唯一的停止条件 |
| ② 托付左子树 | `left = invertTree(root->left)` | 停在这一行，等「翻好的左子树」回来 |
| ③ 托付右子树 | `right = invertTree(root->right)` | 同上，此时仍未改动任何指针 |
| ④ 交换 | `root->left = right; root->right = left;` | 全题唯一的实际动作，O(1) |
| ⑤ 交还 | `return root;` | 兑现契约，把成品交给上一层 |

一个容易追问的细节：**交换也能放在递归之前**（前序位置），结果完全一样：

```cpp
if (root == nullptr) return nullptr;
std::swap(root->left, root->right);   // 先换
invertTree(root->left);               // 再分别翻转（此时左右已易位）
invertTree(root->right);
return root;
```

两种写法都保证「每个节点的孩子恰好交换一次」。区别只是时机：后序版自底向上翻好，前序版自顶向下翻好。

### 代码（C++）

```cpp
class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        if (root == nullptr) {
            return nullptr;
        }
        TreeNode* left = invertTree(root->left);
        TreeNode* right = invertTree(root->right);
        root->left = right;
        root->right = left;
        return root;
    }
};
```

### 代码（Python）

```python
class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if root is None:
            return None
        left = self.invertTree(root.left)
        right = self.invertTree(root.right)
        root.left = right
        root.right = left
        return root
```

### 复杂度分析

- **时间复杂度**：`O(n)`。每个节点恰好进栈一次、出栈一次，各做 O(1) 的指针交换。
- **空间复杂度**：`O(h)`，`h` 是树高。同一时刻栈里只有「从根到当前节点」的一条路径。平衡树 `h = log n`，退化成链表时 `h = n`。以样例树 `[4,2,7,1,3,6,9]` 为例，最深时栈中有 4 帧（含触底的那一帧）。

> 注意区分：`n` 是访问总量，`h` 才是同时在场的人数。递归的栈空间看后者。

## 小结

### 写任何树递归，先回答三个问题

1. **边界是什么？** 什么时候可以不做任何事直接返回。
2. **子问题的契约是什么？** 一句话说清「给递归什么、它还你什么」，说清之后就不要再怀疑它。
3. **当前这一层做什么？** 假设契约成立，我这层需要几步操作。

想不通的时候不要盯着代码硬想，**拿一棵三五个节点的小树手工跑一遍**，把每次调用和每个返回值写下来。

### 易错点

- **不用局部变量直接赋值**。`root->left = invertTree(root->right); root->right = invertTree(root->left);` 是错的：第一行覆盖了左指针，原左子树整棵丢失，而右子树被翻了两次（等于没翻）。
- **以为叶子要特判**。叶子交换的是两个 `nullptr`，走的是和非叶子完全相同的流程，不需要任何特殊处理。
- **以为根节点最先交换**。恰恰相反——交换的前提是「两个孩子都已翻好」，这个条件只能从叶子往上满足，所以根最后交换。
- **忘记空树输入**。`root = []` 是合法输入，base case 顺带把它处理了。
