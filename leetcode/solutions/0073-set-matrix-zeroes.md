# 73. 矩阵置零

> **难度**：中等　**标签**：数组 · 矩阵 · 原地算法
> **链接**：[LeetCode 73](https://leetcode.cn/problems/set-matrix-zeroes/)

## 题目

给定一个 `m x n` 的矩阵，如果一个元素为 `0`，则将其所在行和列的所有元素都设为 `0`。请使用**原地**算法。

**示例 1**

```
输入：matrix = [[1,1,1],[1,0,1],[1,1,1]]
输出：[[1,0,1],[0,0,0],[1,0,1]]
```

**示例 2**

```
输入：matrix = [[0,1,2,0],[3,4,5,2],[1,3,1,5]]
输出：[[0,0,0,0],[0,4,5,0],[0,3,1,0]]
```

**提示**

- `m == matrix.length`，`n == matrix[0].length`
- `1 <= m, n <= 200`
- `-2³¹ <= matrix[i][j] <= 2³¹ - 1`

**进阶**：能否只用常量空间？

## 我的理解

### 难的不是「清零」，是「哪儿能记下要清谁」

最直觉的做法是：扫到一个 `0`，立刻把它所在的行和列全抹掉。这样是错的——**新抹出来的 `0` 会被当成「本来就有的 `0`」**，继续污染它所在的行列，一路连锁下去整张矩阵就全黑了。

所以顺序必须是：**先只看不改，把要清的行列记全；记全了再统一动手。** 问题于是被压缩成一句话：

> 「哪几行、哪几列要清」这份名单，存在哪儿？

开两个数组 `row[m]`、`col[n]` 当名单是最省事的，但要额外 `O(m+n)` 空间，过不了进阶要求。

### 破局：名单就写在矩阵自己身上

关键观察：**矩阵的第一行和第一列本来就是矩阵的格子，它们天然可以兼任名单。**

- 「第 `i` 行要清零」→ 把 `matrix[i][0]` 置 0；
- 「第 `j` 列要清零」→ 把 `matrix[0][j]` 置 0。

第一趟扫描只写名单、不动别的格子，所以不会连锁污染。第二趟扫描时，每个 `matrix[i][j]` 抬头看一眼自己那行的名单和那列的名单，只要有一个是 0，就把自己置 0。

剩下唯一的问题：**首行首列被借去当名单了，它们自己要清零的信息往哪放？**

- 首行用一个 `bool first_row_has_zero` 单独存——「整行清」这件事只需要一位信息；
- 首列**不需要**额外的变量。因为 `matrix[0][0]` 这个位置天生有歧义：它既是「第 0 行」的名单格，也是「第 0 列」的名单格。用 bool 把「第 0 行要不要清」搬走之后，它就只剩一个身份——**第 0 列的名单格**。而它正好胜任：第一趟为第 0 列里出现的每个 `0` 都会把它写成 0；如果第 0 行原本就在第 0 列有 `0`，它本来就是 0。所以扫描结束后 `matrix[0][0] == 0` ⟺ 第 0 列含 0。

### 三个必须讲清楚的细节

这三处都不是「顺手这么写的」，改动任何一处都会出错。

**细节一：第一趟为什么从 `i = 1` 开始**

如果 `i` 从 0 开始，第 0 行自己那些 `0` 也会被当成「某行有 0」写进名单，顺手把 `matrix[0][0]` 置成 0——而它同时是**第 0 列的名单格**，于是第 0 列被冤枉地整列清零。

反例 `[[1,0],[2,3]]`：第 0 行的 `0` 只该清掉第 0 行和第 1 列，答案是 `[[0,0],[2,0]]`；`i` 从 0 开始会把 `matrix[0][0]` 写成 0，第 0 列被误清，得到 `[[0,0],[0,0]]`。

**细节二：第二趟内层 `j` 为什么必须倒着走**

第二趟里 `j = 0` 那一格是特殊的：条件命中时，**写的就是 `matrix[i][0]` 自己**——也就是「第 `i` 行要清」的名单格。名单格一旦被写成 0，这一行**后面**的格子再去看行名单，看到的就都是 0 了。

倒着走（`j` 从 `n-1` 降到 `0`）恰好把这次写入安排在这一行的**最后一格**，等它发生，这一行已经清完了，不会被自己误伤。

反例 `[[0,1],[2,3]]`：正确答案是 `[[0,0],[0,3]]`（第 0 行和第 0 列清零）。内层改成升序时，`j = 0` 因 `matrix[0][0] == 0` 把 `matrix[1][0]` 写成 0，紧接着 `j = 1` 看到行名单是 0，就把本不该清的 `matrix[1][1]` 也清了，整张矩阵全 0。

> 我按这个反例做了对拍：内层升序的版本在 20 万组随机矩阵里错了 3.2 万组，倒序版本一次没错。**倒序不是风格偏好，是这套写法能成立的前提。**
> 想摆脱这个顺序依赖也有办法：清 `j = 0` 之前先把 `matrix[i][0]` 的值备份下来再判断，或者干脆再开一个 `first_col_has_zero` 把第 0 列也单独处理——代价是多一处状态，不如倒着走省事。

**细节三：第 0 行必须留到最后**

`first_row_has_zero` 那次填充必须放在最后。因为在此之前，第 0 行一直在充当「各列的名单板」；一旦提前抹掉，所有列名单就没了，第 1 行往下的列清零会全部失效。

### 四个阶段的顺序

| 阶段 | 代码 | 作用 | 为什么在这个位置 |
| ---- | ---- | ---- | ---------------- |
| ① 记住首行 | `first_row_has_zero = contains(matrix[0], 0)` | 首行自己的命运 | 必须最先；晚了 `matrix[0]` 已经被当名单改写了 |
| ② 写名单 | 双层循环，`i` 从 1 起 | 用首行首列记录要清的行列 | 只写名单，不改别的格子，所以不连锁 |
| ③ 照名单清零 | 双层循环，`j` 倒序 | 清掉第 1 ~ m-1 行 | 名单还在，不能先动首行首列 |
| ④ 处理首行 | 填充 `matrix[0]` | 清掉第 0 行 | 必须最后；此前首行一直是名单板 |

**一句话概括：第一趟把「谁要清零」写进首行首列，第二趟照单清零，最后再回过头处理首行——全程只借矩阵自己的格子当记事本，所以额外空间是 `O(1)`。**

## 解题步骤

### 思路一：两个标记数组（`O(m + n)` 空间）

把「记名单」和「照名单清」分成两趟走，这个骨架是对的——只是名单放在了矩阵外面。

```cpp
void setZeroes(vector<vector<int>>& matrix) {
    int m = matrix.size(), n = matrix[0].size();
    vector<bool> row(m, false), col(n, false);

    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            if (matrix[i][j] == 0) row[i] = col[j] = true;

    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            if (row[i] || col[j]) matrix[i][j] = 0;
}
```

### 思路二：复用首行首列（核心解法）

名单里存的信息只有「是 / 否」一位，而矩阵里全是现成的格子，那就把名单搬进去：首列存行名单，首行存列名单。上面那三个细节，就是把这个想法落地的全部代价。

### 代码（C++）

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        int m = matrix.size();
        int n = matrix[0].size();
        bool first_row_has_zero = ranges::contains(matrix[0], 0);

        for (int i = 1; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (matrix[i][j] == 0) {
                    matrix[i][0] = matrix[0][j] = 0;
                }
            }
        }

        for (int i = 1; i < m; i++) {
            for (int j = n - 1; j >= 0; j--) {
                if (matrix[i][0] == 0 || matrix[0][j] == 0) {
                    matrix[i][j] = 0;
                }
            }
        }

        if (first_row_has_zero) {
            ranges::fill(matrix[0], 0);
        }

        return;
    }
};
```

C++ 版本说明：`ranges::contains` 是 C++23，`ranges::fill` 是 C++20，LeetCode 上选 C++23 即可。要兼容 C++17，把 `contains` 换成 `find` 或手写循环、`fill` 换成循环赋值。

### 代码（Python）

```python
class Solution:
    def setZeroes(self, matrix: List[List[int]]) -> None:
        m, n = len(matrix), len(matrix[0])
        first_row_has_zero = 0 in matrix[0]

        for i in range(1, m):
            for j in range(n):
                if matrix[i][j] == 0:
                    matrix[i][0] = matrix[0][j] = 0

        for i in range(1, m):
            for j in range(n - 1, -1, -1):      # 同样必须倒序
                if matrix[i][0] == 0 or matrix[0][j] == 0:
                    matrix[i][j] = 0

        if first_row_has_zero:
            matrix[0] = [0] * n
```

### 复杂度分析

- **时间复杂度**：`O(m·n)`。两趟完整遍历，每个格子常数次比较 / 赋值。
- **空间复杂度**：`O(1)`。只多了一个 `bool`；名单写在矩阵自己的首行首列里，没有额外数组。

> 注意：`first_row_has_zero` 这一个 `bool` 不随输入规模增长，属于常数空间，不算破功。

## 小结

### 易错点

- **边扫边清**：新产生的 `0` 被当成原有的 `0`，连锁污染，最后整张矩阵全黑。
- **第二趟内层 `j` 写成升序**：`j = 0` 时写下的行名单会被同一行后面的格子读到，误清整行。见「细节二」。
- **第一趟外层 `i` 从 0 开始**：第 0 行自己的 `0` 会被误记成「第 0 列要清」，第 0 列被冤枉清零。见「细节一」。
- **提前清第 0 行**：列名单随之丢失，第 1 行往下的列清零全部失效。
- **忘了 `first_row_has_zero`**：其他行列都对了，唯独首行没清。

### 可迁移的套路

需要一份 `O(1)` 的「标记名单」时，先问三句：

1. 名单里每一项需要存多少信息？——如果只是一位布尔，「借用现成格子」就有戏。
2. 借用哪块？——挑**最后才用得上**的那块。这里首行首列正好是最后两个阶段才处理的对象。
3. 被借用的那块，自己的信息谁来保管？——通常是「一个变量」或「另一个还没被占用的格子」。想清楚这一点，剩下的就是处理顺序。

### 同族题目

都是「空间不够，把信息塞回原数组」：把原数据里某一位改造成标记位或状态位。

| 题目 | 借用谁当标记 | 格子里实际存了什么 |
| ---- | ------------ | ------------------ |
| 73 矩阵置零 | 首行 + 首列 | 「这一行 / 列要清零」 |
| 289 生命游戏 | 每个格子自己的高位 | 旧状态 + 新状态，两代状态挤在一个 int 里 |
| 448 找到所有数组中消失的数字 | 数值对应的下标（取负号） | 「这个数出现过」 |
| 41 缺失的第一个正数 | 下标 ↔ 数值互换 | 「值 v 应该待在下标 v-1」 |

> 本文 C++ 代码已与暴力实现对拍 200000 组随机矩阵（`1 ≤ m, n ≤ 6`，取值含负数和 `0`）结果完全一致；示例、`1×1`、单行、单列、全零、无零等边界用例同样通过。
