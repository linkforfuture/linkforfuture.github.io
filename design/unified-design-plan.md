# Linkforfuture 统一设计方案

日期：2026-09-27。状态：历史设计提案。已完成全站改造；当前实现与后续约束以 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 和根目录 [AGENTS.md](../AGENTS.md) 为准。本文件保留最初的设计推导，其中规划路径不代表当前实际结构。

## 1. 设计方向

将网站定位为「集合通信与 AI 基础设施的个人技术知识库」。兼顾个人介绍、长期阅读和交互实验。采用浅灰背景、白色阅读面、深色文字和靛蓝强调色，减少大面积渐变、装饰图标及重复卡片。

统一的是品牌、导航、排版、组件与内容组织；Markdown 与 HTML 可以继续并存。读者看到的是「笔记、设计文档、交互图解、实验」，无需按文件扩展名选择入口。

## 3. 信息架构

全站一级导航建议为：**首页 / 专题 / 图解实验 / 关于我**。

专题按知识领域组织：

- 集合通信：XCCL、HCCL、拓扑、性能分析。
- GPU 编程：CUDA 环境、课程、实验与学习记录。
- 算法与数据结构：LeetCode 题解及相应交互演示。
- 模型与推理：Transformer shape、prefill/decode、KV Cache 等。

「工作文档」保留现有独立入口，内部沿用需求、设计、拓扑、分析、HCOMM 的目录，避免一次改动现有知识结构。在全站索引中增加领域与内容类型，允许同一篇内容从专题和工作文档两处找到，指向同一个 URL。

「图解实验」是跨专题的内容集合；同一图解可以同时出现在专题和图解列表中。随笔等到有实际内容后再增加入口。

首页顺序：

1. 个人简介：Linkforfuture；「集合通信与 AI 基础设施」；一句记录范围；关于我入口。
2. 专题入口：集合通信、GPU 编程、算法与数据结构、模型与推理。
3. 精选内容：人工选择 3–5 篇有代表性的笔记或图解。
4. 最近更新：紧凑文章列表，使用真实内容更新时间；没有可靠日期时暂不显示。
5. 页脚：GitHub、站点说明。

首页无需逐篇罗列全部内容。列表显示标题、简述、领域和内容类型；格式只在「查看源码」时出现。

## 4. 一套视觉规范

建议首期先完成浅色主题。深色模式后续统一接入，图表也必须一起检查。

| 项目 | 建议值 | 使用方式 |
| --- | --- | --- |
| 页面背景 | `#F7F8FA` | 外层背景 |
| 内容表面 | `#FFFFFF` | 导航、必要的卡片、演示区 |
| 主文字 | `#1F2937` | 标题与正文 |
| 次要文字 | `#64748B` | 摘要、元信息 |
| 细分隔线 | `#E2E8F0` | 列表、侧栏、表格 |
| 品牌色 | `#4F46E5` | 链接、选中状态、主要动作 |
| 淡强调背景 | `#EEF2FF` | 选中导航与提示 |
| 成功 / 提醒 / 错误 | `#047857` / `#B45309` / `#B91C1C` | 状态语义，必须同时给出文字 |
| 正文字体 | 系统中文无衬线字体 | 无额外字体下载依赖 |
| 代码字体 | Cascadia Code / Consolas / monospace | 代码、命令、数值 |
| 正文 | 17px，行高 1.85 | 窄屏可降到 16px |
| 标题 | 页面 32–40px；二级 24px；三级 20px | 相同层级保持一致 |
| 元信息 | 13–14px | 不承担主要阅读内容 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48px | 避免每页临时定义 |
| 圆角 | 控件 6px，内容区 10px | 胶囊形仅用于短标签 |
| 阴影 | 默认无或极轻 | 浮层才使用明显阴影 |

文章正文采用连续排版；卡片用于专题入口与有边界的互动区域。章节间以留白和标题分层，避免每段文字都放进卡片。

图解中的蓝、橙、绿、紫可以保留，用来表示 rank、通路、维度或状态。图内颜色与网站品牌色分别管理，不把已有语义配色强行改成靛蓝。

## 5. 页面模板

### 首页与内容目录

内容宽度约 1120px。精简页头、清楚的专题入口、紧凑文章列表。专题页复用相同列表组件，可按笔记、设计、图解、实验筛选。

### 阅读页：同时用于 MD 和文章型 HTML

桌面：全站页头 + 左侧专题目录 240px + 正文约 760px。足够宽时可增加右侧本页目录约 180px；空间不足先将本页目录折叠到标题下。

文章头统一为「面包屑 → 标题 → 一句摘要 → 类型、专题、真实更新日期」。正文统一标题、段落、代码、表格、引述、提示块、图片与图注。页尾提供相关图解、上一页/下一页及源文件入口。

左侧目录表示「专题中有哪些文章」，本页目录表示「当前文章有哪些章节」，不要混为同一导航树。

### 交互图解页

沿用站点页头、面包屑、文章头与按钮。说明文字仍控制在约 760px，演示区可以扩到 1120–1280px。图表、播放控制与参数控件位于演示区内。

复杂图优先提供局部横向滚动或展开查看，不能把全部文字缩到手机上不可读。文本解释应在脚本不可用时继续可读。

### 简历页

屏幕端呈现共同品牌与返回路径；打印时隐藏网站导航、交互控件和阴影，继续按 A4 版式输出。学习路径归入学习内容，可先保留原锚点入口，再逐步拆分。

## 6. MD 与 HTML 如何共用设计

建议第一阶段沿用现有静态托管与 Docsify，不为换视觉同时迁移框架。

推荐新增公共资源（下列为规划路径，并非已经实现）：

```text
assets/
  css/
    tokens.css          # 全站颜色、字体、宽度与间距
    shell.css           # 页头、导航、面包屑、页脚
    prose.css           # 统一文章排版
    components.css      # 按钮、标签、提示、代码与列表
    docsify-adapter.css  # 将 Docsify 结构映射到上述规范
  js/
    site-shell.js       # 共享导航行为
    docsify-adapter.js  # 切页后的文章头、目录等增强
  vendor/
    docsify/            # 核对版本后再合并
content-index.json      # 全站内容元数据
templates/
  article.html          # 新 HTML 文章模板
  interactive.html      # 新交互图解模板
```

Markdown：继续在原来的 `.md` 中写内容，通过 Docsify 渲染，适配层将其正文接到共同排版规则。现有 Markdown 链接、图片相对路径和代码高亮需要保持有效。不要要求每篇 Markdown 添加样式。

HTML：普通文章使用共同文章模板；交互页面在共同外框内保留专属脚本、SVG 和样式。新增样式以页面根类名限定范围，例如 `.demo-allgather`；避免覆盖全站的 `button`、`header`、`.sidebar` 等通用选择器。旧页面要逐页清理冲突，不能靠最后加载一份 CSS 解决全部问题。

两种格式共享语义结构，但不要求拥有相同 DOM。可以用 `.site-prose` 与 Docsify 的 `.markdown-section` 作为两种排版入口，并谨慎排除交互组件内部元素。

Docsify 本身提供主题定制和插件钩子，适合实现此适配层。参考官方[主题文档](https://docsify.js.org/#/themes)与[插件文档](https://docsify.js.org/#/write-a-plugin)。实施时必须核对仓库内现有版本，不直接套用新版主题变量，也不顺手升级运行时。

不将 MD 批量转换成手写 HTML，也不将已有交互 HTML 强行塞进 Markdown。iframe 仅用于难以解耦的独立演示或临时兼容，不作为默认文章容器。

## 7. 内容登记与日常维护

建议统一索引字段：`id`、`title`、`summary`、`topic`、`kind`、`source`、`url`、`updated`、`featured`、`order`。其中 `kind` 是笔记/设计/图解/实验；`source` 才区分 md/html。

例如现有文章可以登记为：

```json
{
  "id": "allgather-nhr-localcopy",
  "title": "AllGather NHR 减少 LocalCopy",
  "summary": "需求与设计说明",
  "topic": "集合通信",
  "kind": "设计",
  "source": "work/srs-sd/allgather-nhr-reduce-localcopy-srs-sd.md",
  "url": "/work/#/srs-sd/allgather-nhr-reduce-localcopy-srs-sd",
  "updated": null,
  "featured": false
}
```

初期索引用于首页和跨专题目录；侧栏分组可以继续保留手工编辑。后续如自动生成侧栏，必须保留现有分组、顺序与稳定链接。数量从索引计算，更新时间由实际内容修改确认，不用文件复制时间冒充。

第一阶段保留各专题现有全文搜索，清楚标明范围。未来全站搜索统一收录渲染后的 MD 正文与 HTML 文章正文，过滤导航和脚本，结果直接跳到现有 URL；仅新增一个搜索框不会自动具备全站搜索能力。

新增内容的流程应缩减为：选择 MD 或 HTML 模板 → 写内容 → 在索引登记 → 检查分类与链接。作者无需再次决定导航和色板。

## 8. 实施顺序与验收

1. **共用基础与三页样板**：建立 tokens、外框和排版；改首页、一个 MD 阅读页、一个 HTML 图解页，确认视觉与交互能够共存。
2. **接入现有页面**：工作文档、CUDA、LeetCode 接入适配层；逐页迁移 XCCL 和 shape 图解；保留原路径、原锚点及简历打印布局。
3. **整理内容入口**：调整 LeetCode 分类，登记内容索引，生成首页精选和专题入口，清理人工计数及重复依赖。
4. **按需求追加能力**：全站搜索、统一深色模式、静态预渲染。搜索与 SEO 成为明确需求后，再评估是否需要生成器迁移。

首轮完成标准：

- 从任意文章能找到首页、所属专题和当前位置；手机端目录可展开并操作。
- MD 与 HTML 的文章头、文字尺寸、代码、表格和链接外观一致。
- 检查桌面与 360px 窄屏；页面主体无意外横向滚动，宽图和代码允许局部滚动。
- 允许浏览器缩放；移除现有文档壳中的 `user-scalable=no` 等限制。
- 键盘可操作导航与图解控件，焦点清晰；减少动态效果设置有效。
- 检查原有深链接、Markdown 相对资源、前进后退、代码复制、搜索范围与图解播放/滑块。
- 打印简历保持 A4 布局，网站外框不进入打印结果。
- 视觉方案文件不接入首页导航，不将设计示意误当作已上线改版。
